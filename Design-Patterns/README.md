## Creational Design Pattern

| Creational Design Pattern | Purpose |
| --- | --- |
| Singleton | Ensure only one object exists. |
| Factory Method | Let subclasses decide which object to create. |
| Abstract Factory | Create families of related objects. |
| Builder | Build complex objects step by step. |
| Prototype | Create new objects by copying existing ones. |

## Structural Design Pattern

| Structural Design Pattern | Purpose |
| --- | --- |
| Adapter | Make incompatible interfaces work together. |
| Bridge | Separate abstraction from implementation. |
| Composite | Treat individual objects and groups uniformly. |
| Decorator | Add behavior dynamically. |
| Facade | Provide a simple interface to a complex system. |
| Flyweight | Share objects to save memory. |
| Proxy | Control access to another object. |


## Behavioral Design Pattern

| Behavioral Design Pattern | Purpose |
| --- | --- |
| Chain of Responsibility | Pass requests through a chain of handlers. |
| Command | Encapsulate requests as objects. |
| Interpreter | Interpret a language or grammar. |
| Iterator | Traverse collections without exposing their implementation. |
| Mediator | Centralize communication between objects. |
| Memento | Save and restore an object's state. |
| Observer | Notify dependents automatically when state changes. |
| State | Change behavior based on internal state. |
| Strategy | Swap algorithms at runtime. |
| Template Method | Define an algorithm skeleton and let subclasses customize steps. |
| Visitor | Add new operations without modifying existing classes. |
